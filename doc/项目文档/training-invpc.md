## 0. 先纠正一件事：什么才是嵌入式工程师的**必会**技能

上一版把「读 `firmware.elf` / `nm` / `objdump`」当成了主线任务。**这是设计错误，已修正。**

| 技能                            | 定位           | 要不要必会 |
| ----------------------------- | ------------ | ----- |
| 读懂**自己项目**的代码结构与调用链           | **日常基本盘**    | ✅ 必会  |
| 用 SWD 打断点 / 监视变量 / 看调用栈       | **日常基本盘**    | ✅ 必会  |
| 从故障码（CFSR/HFSR）倒推到代码行         | **排查核心**     | ✅ 必会  |
| 设计"能证伪假设"的观测点                 | **分水岭能力**    | ✅ 必会  |
| 反汇编 `firmware.elf` / `nm` 查符号 | **极端情况的核武器** | ❌ 不要求 |
| 读 `firmware.bin` 十六进制向量表      | **同上**       | ❌ 不要求 |

**"核武器"什么时候才用**：芯片已经死了（连屏都画不出来、SWD 也连不上、没有任何打印通道）—— 只剩下一个静态文件可以研究时。本次就是这种情况（当时屏上什么都没有），所以掏出来了。**它是例外，不是常态。**

所以本版任务书里：

- **凡是需要跑 `nm`/`objdump`/读二进制的步骤，我来做**。你只需要读结论、做判断。
- 你的任务是**判断和推理**，不是敲命令。

## 0.2 参考表（做题时随手查）

**表 A：CFSR（地址 `0xE000ED28`）的位段划分**

| 位段         | 名称    | 管辖                    |
| ---------- | ----- | --------------------- |
| `bit7:0`   | MMFSR | MemManage（访存保护）       |
| `bit15:8`  | BFSR  | BusFault（总线/取指/入栈）    |
| `bit31:16` | UFSR  | UsageFault（指令用法/非法状态） |

**表 B：UFSR 常用位**

| 位   | 名称         | 官方描述                         |
| --- | ---------- | ---------------------------- |
| 16  | UNDEFINSTR | 未定义指令                        |
| 17  | INVSTATE   | 非法状态（如 EPSR.T=0 想执行 ARM 指令）  |
| 18  | INVPC      | **用非法的 EXC_RETURN 值装载 PC**   |
| 19  | NOCP       | 访问了未使能的协处理器（如 FPU 没开就执行浮点指令） |
| 24  | UNALIGNED  | 未对齐访问                        |
| 25  | DIVBYZERO  | 除零                           |

**表 C：HFSR（地址 `0xE000ED2C`）**

| 位   | 名称       | 含义                                    |
| --- | -------- | ------------------------------------- |
| 30  | FORCED   | 有别的故障**升级**成了 HardFault（因为那类故障的异常被关闭） |
| 1   | VECTTBL  | 取向量时总线错误                              |
| 31  | DEBUGEVT | 调试事件                                  |

**【补齐】** 请把下面这张表填完整（多选题）：

| 项    | 值            | 落在哪个位段             | 第几位 | 名称         |
| ---- | ------------ | ------------------ | --- | ---------- |
| CFSR | `0x00040000` | **UFSR**（bit31:16） | 18  | **INVPC**  |
| HFSR | `0x40000000` | —                  | 30  | **FORCED** |

**再用一句话回答**：HFSR 那位在说什么？

> 它本来是另一类故障（UsageFault），因为**那类故障的异常被关闭了**，所以被"逼"升级成了 HardFault。

**【关键修正】** 你的表述里有一个词要改：**不是"从 ISR 返回 main"**。

- `EXC_RETURN` 这条路径在本次是 **`vPortSVCHandler` 里的 `bx lr`** —— 它发生在**刚进 SVC 处理函数、还没来得及处理任何事**的时候；
- 所以准确说法是：**"异常返回时，CPU 发现要装载进 PC 的那个值不是合法的 EXC_RETURN 格式，于是拒绝返回"**。
- 这个区别重要：它把"任务切出去回不来"和"根本没能切进第一个任务"分开了 —— **本次是后者。**

## T2 —— 找到"谁会做这个动作"

**【做什么】** 现在是**判断题时间**，不用敲命令。请回答下列问题，答不出就找我要提示。

**Q1**：什么指令会让 CPU "用 EXC_RETURN 去装载 PC"？

**【线索】** 这类动作在汇编里长得像 `bx <寄存器>` —— 但**不是每条 `bx` 都算**。只有 `bx` 到**特定格式的值**（高位全 1 的那种）才会被 CPU 当成"异常返回"。

**Q2**：在这个项目里，需要"异常返回"的地方一共几处？

**【线索】** 想任务切换这件事：

- **启动第一个任务**（从头进任务，用 `SVC`）
- **任务之间切换**（任务 A → 任务 B，用 `PendSV`）
  这两件事是同一个函数干的吗？（提示：去看 `.pio/libdeps/.../FreeRTOS-Kernel/portable/GCC/ARM_CM4F/port.c`，找带 `naked` 的函数）

**Q3**：`bx lr` 里的 `lr` 是谁给的？

**【线索】** 三种可能，选一个：

- (a) 函数被调用时 CPU 自动压进 LR 的返回地址；
- (b) 这个函数**自己从内存里读出来**的；
- (c) 上面两个都对，取决于哪个函数。

**【自检 / 预期结果】**

- Q1：能说出"`bx` 到一个高位全 1 的值"；
- Q2：**应该是 2 处**。只找到 1 处 = 你漏了另一条换栈路径；

## T8 —— 为什么"写进去的值"不等于"生效的值"
